# 步骤解释 · dsh-step-explain

把模型正在做的每一步，用**新手能看懂的中文**讲清楚。

> 面向不熟悉 AI 编程工具的用户：不用再猜 "它刚才干了什么"、"这条命令危不危险"、"点允许会怎样"。

[English](README.md) | 简体中文

---

## 它解决什么问题

| 场景 | 没有这个插件 | 有这个插件 |
| --- | --- | --- |
| 模型正在读文件 | 只有一行 `read README.md` | 「正在读取文件 `README.md`」，可展开看影响与能否撤回 |
| 一轮任务结束 | 十几条工具调用堆在聊天里 | 一行汇总「本轮 7 步 · 读取文件 3 · 改动文件 2 · 运行命令 2」，可逐步展开 |
| 弹出权限审批框 | 只有一条命令原文，看不懂要干嘛 | 说清这一步做什么、风险等级、点「允许」/「拒绝」分别会发生什么 |
| 自己写的话太模糊 | 只能删了重打，或者硬着头皮发出去 | 「帮我扩写」改成清楚指令，可采用、可退回、可再让它改 |

## 三个界面

1. **输入框上方**：模型正在跑的那一步，一行中文，按钮「这是什么」展开细节。
2. **每轮回答末尾**：本轮所有步骤的汇总与逐步展开。
3. **权限审批框**：接管命令原文那一行，改成完整解释（风险点 + 两种选择的后果）。

设置里有两个入口：**设置 → 步骤说明**（本插件自己的一个分页，讲得最全，和「免费模型」「小说创作大师」那些插件页并列），以及「设置 → 通用」里的一行（快捷入口）。两处改的是同一份设置，不会打架。

## 设置 → 步骤说明（本插件的分页）

在设置面板左侧导航里点 **步骤说明** 就进来了，页面上分三块：

- **说明的详细程度** —— 「审批框的说明档位」三个按钮并排（基础 / 模型补充 / 完整说明），点一下就换，当前那一档会变成品牌色高亮；按钮只写档位名，「详细程度」这个前缀由行的标题承担，所以三个按钮在窄面板里也排得下（空间不够时自动换行，不会被挤出可视区）。下面一段文字解释每一档分别多给什么。
- **模型** —— 「步骤说明的详细版由哪个模型写」下拉框，选完立即保存。
- **关于** —— 一句话说清哪一档会联网，以及这个插件只做解释、不替你回答审批。

分页沿用 Harness 设置页自己的写法（标题 + 分节 + 行），不引入新依赖，也不需要新的 Host 路由。它只是把通用里那一行和审批框上的档位按钮汇总到一页，状态读的是同一份。

## 把粗糙的话扩写成清楚的指令

输入框上方还有一条「把这句话写清楚」。写了一句自己都嫌模糊的话（比如「把那个 bug 修了」），点「帮我扩写」，模型会把它改写成一句能直接动手的指令：目标、范围、期望结果、怎么验收。然后你可以：

- **采用** —— 把这版写回输入框，文字归你，回车还是你按。
- **退回** —— 把原来的那句话原样放回去，一个字都不改。
- **让它改** —— 展开一个小输入框，写「再短一点」「补上验收标准」，回车或点「改一版」，模型按你的要求重写整段（上一版会一起给它当参考）。

右上角有**三个篇幅档位**并排：**简短 / 适中 / 详细**，点哪个就是哪个（当前那档高亮），不用来回切换。

| 档位 | 改写出来大概是什么样 |
| --- | --- |
| **简短** | 两三句以内，能省的字都省掉，不重复原话。 |
| **适中** | 一句话说清目标，再补必要的范围和期望结果，不逐条罗列。 |
| **详细** | 分点列出目标、范围、步骤、验收方式，每点一句话。（默认） |

**它永远不替你发送**：不点「采用」，输入框里的字一个都不会变；发送始终是你按回车。改写期间输入框照常可用。

> 只有点了「帮我扩写」才会发请求，内容就是你输入框里的那段话（加上你要的修改要求）。不点就不发。

> 第三个界面只做**解释**：不渲染允许/拒绝按钮，不拦截 Enter / Esc，不替你做决定。
> 它只多了右上角一个档位按钮（见下文），这个按钮不会提交任何答案。
> 如果插件这一格出错，界面会自动退回系统原本的显示，审批流程不受影响。

## 全部档位一览（没有只剩两档的地方）

| 位置 | 控件 | 档位 |
| --- | --- | --- |
| 审批框右上角 | 循环按钮（点一下进一档） | 基础 → 模型补充 → 完整说明 |
| 设置 → 步骤说明 / 审批框 | 三个按钮并排 | 基础 / 模型补充 / 完整说明 |
| 输入框上方「把这句话写清楚」 | 三个按钮并排 | 简短 / 适中 / 详细 |

三处都是三档以上，没有一处还停留在「简略 / 详细」两态。审批框的档位在设置分页和审批框自身之间共享同一份状态，改一处另一处跟着变。

## 审批框的说明档位（三档，点一下换一档）

审批框右上角那个按钮会循环切换档位，当前是哪一档就写在哪一档上，刷新后保持：

| 档位 | 你会看到 |
| --- | --- |
| **基础**（默认） | 规则解释：这一步做什么、风险等级、原样命令，以及「允许 / 拒绝」各自会怎样。 |
| **模型补充** | 基础档的全部内容，再加一段模型写的一两句说明，用来补上规则说不到的地方。 |
| **完整说明** | 基础档的全部内容，再加五段固定说明：这个框是干什么的、为什么会弹出来、框里每一行是什么、你能做的选择、注意事项。 |

三档只改**说明文字**，审批流程本身一点没变：允许和拒绝仍然由系统那个审批框的按钮决定，插件这一格永远不提供答案。

**完整说明**这一档是给「第一次遇到、想弄清楚再决定」的场景准备的，讲的是审批框本身，不是模型写的一句话，所以不会出现「模型瞎说」的问题，也不需要联网。

## 解释里有什么

每一步给出三类信息：

- **这一步做什么** —— 例如「在这台电脑上执行一条命令，它能做的事不受限制。」
- **影响** —— 例如「命令会真的执行：可能改动磁盘、安装软件或联网。」
- **能否撤回** —— 例如「取决于命令本身，先看清它要做什么再决定。」

再加上**风险等级**（低风险 / 需留意 / 会动到数据）和**它在操作哪个对象**（文件名、命令、网址、搜索词）。

审批框额外给出：

```
运行 PowerShell 命令                        需留意
在这台电脑上执行一条命令，它能做的事不受限制。
  npm test
点"允许"：命令会真的执行，可能改动磁盘。
点"拒绝"：命令不执行，不会有任何副作用。
以上只是说明，不会替你选择。
```

上面没有「注意」那一行，是因为 `npm test` 不像会毁数据；换成递归删除、强推、`DROP TABLE`、管道进 shell 之类，才会在命令下面多出一行红字提醒。

## 模型补充这一档（可选，接模型）

档位按钮切到「模型补充」时，审批框会多一段由模型写的一两句说明，并用一句话标明这段是模型写的、可能出错。**默认是「基础」档，不会联网。**

- **只在「模型补充」档才发请求**：基础档和完整说明档都不发任何网络请求，所有解释都由本地规则和固定文案生成。
- **发出去的是什么**：只发工具名和这一步的参数原文（命令、文件路径等）和回答语言；不带会话内容、不带整段对话、不带电脑信息。用哪个模型由 Host 按保存的设置自己决定，浏览器不传模型名。
- **用哪个模型**：默认跟当前会话的默认模型一致（聊天用哪个，它就问哪个）。想让它单独用别的模型，在设置页里选（见下一节）。
- **失败了怎么办**：没配模型、超时、报错，都只是这一段不出现；上面的规则解释照旧，审批流程不受影响。
- **档位记在浏览器里**：每个浏览器各自记住，刷新后保持。

> 切到「模型补充」，等于同意这一段参数文字离开本机去模型服务。介意的话停在「基础」或「完整说明」即可，这两档完全不联网。

### 指定详细版用哪个模型（设置页里选，会保存）

打开 **设置 → 步骤说明**（或 **设置 → 通用** 里那一行），找到「步骤说明的详细版由哪个模型写」，在下拉框里选一个即可，默认是「跟随聊天模型」。列表就是这台机器当前真正可用的模型。

**选中即保存**：写进这台机器的 profile 配置（和官方模型设置页同一套写入路径），不是只存在浏览器里。离开设置页、刷新页面、重开 Harness 都还在；换浏览器也一样，因为是按机器存的。想还原就选回「跟随聊天模型」。

写不进去的时候（比如配置文件只读），这一行会明确显示「没保存成功，仍然沿用上一次的设置」，不会假装已保存。

### 指定详细版用哪个模型（写在配置里）

如果想让**所有**打开这台机器的人默认都用某个模型，在 `cordis.patch.yml` 里取消注释并填上：

```yaml
- insert:
    - id: step-explain
      name: dsh-step-explain
      config:
        provider: deepseek
        model: deepseek-chat
```

只填一半（比如只有 `provider`）视为没填，会退回跟随聊天模型。改完重启或重载插件生效。

优先级从高到低：**设置页里自己的选择 → 配置里的 `provider`/`model` → 当前聊天模型**。

也可以直接在插件管理里改这个条目的配置，无需编辑文件。

按含义分成七类，未列出的工具走通用兜底（不会出现原始 key）：

| 类别 | 例子 | 风险 |
| --- | --- | --- |

| 改动文件 | `write` `edit` `str_replace_editor` | 需留意 |

## 安装

已在本机装好（`link:E:/dshwork/dsh-step-explain`，并已加入 profile 的 bundles）。换一台机器时：

```bash
# 在 Harness 里通过插件管理执行
plugin_manager install_bundle target="link:E:/dshwork/dsh-step-explain"
```

安装后刷新页面即可生效。它没有必填配置、不写文件；只有你手动打开详细版时才会调用模型。

## 关闭

编辑 `cordis.patch.yml`：

```yaml
- insert:
    - id: step-explain
      name: dsh-step-explain
      disabled: true
```

## 自检

```bash
node selftest.mjs      # 界面与解释层
node hostselftest.mjs  # Host 半边（路由、校验、失败兜底）
```

Node 自检，无依赖（Host 自检用假 Context，不联网）。覆盖：分类兜底、风险判定、危险命令识别、参数残缺/畸形 JSON、运行中与已结束两种工具节点、隐藏节点过滤、中英文案对齐、源码里每个 `t('...')` key 都存在、三个界面组件在「无内容 / 运行中 / 已结束 / 审批」四种状态下的实际渲染文本、审批框三档的差异（基础档不联网也不加段落、模型补充档只多一段模型说明、完整说明档确实多出五段且明显更长，且三档都只有档位按钮、没有任何允许/拒绝控件）、档位的循环切换与旧值兜底（存着旧的 `on`/`off` 或乱码时回到基础档）、设置页那一行的读写（读回已保存的选择、保存成功才改显示、保存失败与读不到时各有明确提示）、设置分页的内容与三档按钮（三档同时在列、当前档标记 `aria-pressed`、选档写入同一个存储键、页面上写清了哪一档联网与只读边界）、**在真实 hook 运行时里真的点一次分页上的每个档位**（点击后存储更新、重新渲染后当前档跟着变、能来回切，覆盖「能看见但点不动」这一回归）、选中态样式的层叠顺序（选中规则必须排在基础规则之后、且排在 `:hover` 之后，否则同优先级下会被基础规则盖掉，三个按钮看起来一模一样——这正是「点了没反应」的元凶）、以及 `apply` 实际注册的那几个格（四个聊天面 + 设置分页 + 通用一行，分页 `id`/`locale` 导航标签正确，两个 dock 格各用独立 `id`，且没有任何格注册审批答复）、扩写面板的「不写草稿 / 采用 / 退回 / 让它改 / 失败」整条流程（含 Enter 不会提交消息）、扩写篇幅的三档（三档同时在列、默认「详细」、点击后高亮移动且三档不被折叠成两档）、Host 端三档各自生成不同的 system prompt（并断言三份 prompt 互不相同，防止某一档被静默折进另一档）、**设置行与设置分页共用同一个模型下拉框**（两处渲染出的 `select` props 与选项逐项相同，且源码里 `dse-select` 只构造一次，防止两份实现日后各自漂移）；以及 Host 端的请求校验（类型、必填、长度上限、模型对必须是 provider+model、未知篇幅被拒）、只有 `text-delta` 进入正文、模型优先级（设置页保存的选择 → 配置 → 聊天默认）、**profile 读取有缓存且保存后立即失效**（explain / rewrite / 设置三个路由共用同一次读取，而不是各读一次——缓存按 Loader 条目而不是上下文对象做键，因为三个路由各自持有不同的派生上下文）、模型输出清理（代码围栏与前缀）、模型报错/无路由/无默认模型时一律回 200 空结果，以及模型设置的读取、保存、清除、非法输入被拒（400/415）与配置只读时报 409 而不假装成功。

## 已知边界

- 审批框的接管靠「单槽位渲染最低优先级条目」。若另一个插件也用更低的优先级抢同一个槽位，谁渲染取决于加载顺序，这是当前插件生态的通用限制（代码里标了 `shortcut:`）。插件卸载或崩溃时系统原本的命令行自动回来。
- 风险等级是启发式：按工具类别 + 危险命令正则判断，不猜模型意图，可能把安全命令标成「会动到数据」。
- 详细版的模型说明是模型写的，可能不准；正文上限 600 字，且不参与任何判断，只是多一行参考。
- 扩写也是模型写的，可能补进你没说过的东西（它被要求不要编造，但不能保证）；采用前扫一眼。改写正文上限 4000 字。
- 扩写面板的「让它改」按上一版重写，不保留更早的历史：连续改多轮后，只有最近一版是参考。想从头来，点「重新扩写」即可。
- 设置页里的模型选择存在这台机器的 profile 配置里（不是浏览器本地存储）：换浏览器仍然生效；配置文件只读时选不进去，那一行会明确说没保存成功。想让所有人默认都用某个模型，也可以用配置文件里的 `config`。
- profile 的读取在进程内缓存，保存时会立刻失效；但**手改 `cordis.patch.yml` 不会马上被察觉**，要等插件重载（代码里标了 `shortcut:`）。
- 未做浏览器内的视觉走查；结构与文案由自检覆盖，控件、宽度、配色沿用系统插件同样的 token 和写法。

## 实现说明

- **纯前端为主**：Client 半边负责全部解释、三个界面、扩写面板和设置页（分页 + 通用里那一行）；Host 半边提供三个小路由（详细解释、扩写、模型设置的读写）。
- **只读**：注册六个渲染格（三个聊天界面 + 设置页分页 + 通用里一行 + 扩写面板），不订阅事件、不改会话、不发送消息、不碰工具权限。唯一写操作是你点「采用 / 退回」时把文字写回输入框。
- **扩写只改输入框**：走的是输入框自己的 `inputActions.setDraft`，和手动粘贴等价；不提交、不排队、不触发模型。改写结果只当文本处理，不解析成指令。
- **审批框只替换「命令原文」那一行**：单槽位渲染最低优先级的条目，插件用更完整的解释盖住系统那一行，因此必须自己再显示一次命令；这一格崩溃时插槽会自动交还系统渲染。
- **两条路由都走 Connection 的认证栅栏**：`ctx.connection.fetch.register` 注册 `/api/step-explain.detail` 与 `/api/step-explain.rewrite`，只有 owner 主体的页面能调用；不自己开 HTTP 端口、不绕过鉴权。
- **设置页那一行不新增依赖**：模型选择通过插件自己的 `api/step-explain.model` 路由读写，Host 端用 Harness 自带的 `configEditor` 写进 profile 补丁，和官方模型设置页是同一条写入路径；因此不需要 schemastery，也不需要重启。配置文件只读时那一行显示「没保存成功」，选择不会被改动。缺 `remote.session` 时下拉框只剩「跟随聊天模型」，其余功能不受影响。
- **代码两处**：`client.js` ≈ 1300 行（含字典），`index.js` ≈ 359 行。
